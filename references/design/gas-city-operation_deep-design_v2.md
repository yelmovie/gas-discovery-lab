> **Science World / 초등 4학년 2학기 과학 「여러 가지 기체」**  
> 기존 PRD·TRD·10개 샘플 화면·퀘스트/미션/게이미피케이션 강화 원칙을 통합한 심화 설계 문서

# 0. 문서 목적

이 문서는 지금까지 설계한 **「기체 도시 대작전」**을 폐기하거나 처음부터 다시 만드는 문서가 아니다.

기존에 확정된 다음 요소는 유지한다.

- 제목: **기체 도시 대작전**
- 대상: 초등학교 4학년
- 구조: **5 Mission / 총 10개 핵심 화면**
- 가로형 태블릿 웹앱
- 전자칠판 활용
- 3D + 2D/2.5D 혼합
- Phaser + Three.js + DOM/CSS UI
- 로컬 저장 / 이어하기
- 기체 도시 세계관
- 공기의 무게, 온도·압력과 부피, 여러 기체의 성질과 이용, 공기 장치 설계
- 단순 퀴즈가 아닌 수행형 탐구
- 실시간 시뮬레이션, 전후 비교, 재실험, TEST
- 의미 없는 로봇/부엉이 캐릭터 사용 금지

이번 심화안의 핵심은 기존 화면을 **“예쁜 10장”**에서 끝내지 않고,

> **QUEST → ACTION → REACTION → THINK → RETRY → EVIDENCE → WORLD CHANGE → FINAL REPORT → FINAL ACTION**

이 실제로 돌아가는 하나의 연결된 과학 게임으로 만드는 것이다.

# 1. 설계 핵심 한 줄

학생은 기체 도시의 **에어 엔지니어**가 되어 멈춘 도시의 원인을 조사하고, 실험으로 증거를 확보하며, 도시 시설에 알맞은 기체를 공급하고, 마지막에는 공기의 성질을 이용한 장치를 직접 설계하여 도시의 중앙 공기 코어를 복구한다.

학생의 마지막 경험은

> “기체 문제를 풀었다.”

가 아니라

> **“내가 실험으로 알아낸 과학 원리와 직접 만든 장치로 도시를 다시 움직였다.”**

가 되어야 한다.

# 2. 적용 성취기준

본편 직접 성취기준은 다음 네 가지를 중심으로 한다.

- **[4과15-01]** 실험을 통해 기체가 무게가 있음을 설명할 수 있다.
- **[4과15-02]** 온도나 압력에 따라 기체의 부피가 달라지는 현상을 관찰하고, 우리 주변에서 예를 찾을 수 있다.
- **[4과15-03]** 일상생활에서 이용되는 기체의 종류와 성질을 조사하고, 여러 가지 기체에 대해 흥미를 느낄 수 있다.
- **[4과15-04]** 기체의 성질을 이용하여 작동시킬 수 있는 장치를 설계하고 만들 수 있다.

## 과학 내용 가드레일

다음은 본편에서 사용하지 않는다.

- 보일 법칙, 샤를 법칙 명칭 및 공식
- 절대온도, 압력 단위 계산
- 분자·입자 모형을 이용한 원인 설명
- “압력이 커지면 입자들이 가까워진다”와 같은 입자 수준 설명
- 산소·이산화탄소 발생 장치 실험
- 향불, 석회수 등을 이용한 6학년형 기체 확인 실험
- 헬륨 흡입 체험
- 실제 압축가스 용기 조작을 유도하는 연출
- 수소 폭발 등 위험 행동을 게임 재미 요소로 활용

온도와 압력에 따른 부피 변화는 **관찰 가능한 현상과 전후 비교** 수준으로 다룬다.

# 3. 샘플 페이지 반영 진단

지금까지 생성한 10장 샘플의 비주얼 방향과 인터랙션 표현은 상당 부분 유지한다. 다만 실제 구현 시 과학적 정확성과 게임 흐름을 위해 일부 수정한다.

## 3-1. 유지할 것

### 공통 비주얼
- 밝은 청록·하늘색·흰색 중심의 미래형 기체 도시
- 금색/황동색 밸브·관 연결부
- 투명 파이프와 공기 흐름 연출
- 큰 화면에서도 읽히는 큼직한 패널
- 가로형 16:9
- 상단 Mission 진행 표시
- 왼쪽 미션 패널
- 중앙의 실제 학습 조작 공간
- 하단의 기록/도구/상태 패널
- 모듈형 CSS UI
- 이미지에 버튼과 글자를 굽기보다 실제 구현에서는 DOM/CSS로 분리

### 캐릭터
샘플에서 확립된 세 캐릭터를 프로젝트의 고정 NPC로 활용한다.

1. **여우 발명가 — 에어**
   - 역할: 장치·공학·기체 이동 관련 퀘스트
   - 담당: Mission 1, Mission 5
   - 행동: 연결, 조립, TEST 힌트 제공

2. **고양이 연구원 — 루미**
   - 역할: 측정·비교·증거 분석
   - 담당: Mission 2, Mission 3
   - 행동: 측정 조건 확인, 연구 기록 분석

3. **다람쥐 관제원 — 포포**
   - 역할: 도시 지도·기체 배송·Evidence 전달
   - 담당: Mission 4, Final Report
   - 행동: 시설 요청 전달, 연구 결과 보관 및 운반

캐릭터는 장식물이 아니라 **게임 시스템**으로 사용한다.

## 3-2. 반드시 수정할 것

### 수정 1 — 압력 화면의 입자 설명 삭제
샘플 중 압력 화면에

> “압력이 높아지면 기체 입자들이 가까워져…”

같은 문구가 들어간 경우 실제 제품에서는 삭제한다.

4학년에서는

> **“압력이 높아질 때 기체가 차지하는 부피가 줄어드는 현상을 관찰했다.”**

수준으로 제시한다.

### 수정 2 — 귀여운 구름을 ‘기체 입자’처럼 사용하지 않기
구름 캐릭터가 압축되는 연출은 학생이 기체 입자 모형으로 오해할 수 있다.

실제 구현에서는

- 투명한 유연 용기
- 풍선형 막
- 피스톤 안 공기 공간
- 부피를 보여주는 외곽선

으로 변화 자체를 보여준다.

### 수정 3 — 여러 기체 정보 카드 범위 정리
샘플의 기체 카드는 다음 중심으로 단순화한다.

- **질소:** 식품 포장 등
- **산소:** 사람의 호흡과 관련된 이용
- **이산화탄소:** 탄산음료, 일부 소화기 등
- **헬륨:** 공기보다 가벼워 풍선 등에 이용 — 선택적 확장

기체 정보를 많이 암기시키지 않는다.

### 수정 4 — 마지막 화면 자동 완료 구조 금지
샘플의 마지막 화면처럼 Stage 5가 끝나자마자

> “기체 도시 복원 성공!”

을 보여주지 않는다.

먼저 학생이

1. Evidence 5종을 NPC에게 직접 제출
2. Final Report 확인
3. 자신이 만든 공기 장치를 중앙 코어에 연결
4. 마지막 밸브/레버를 직접 작동
5. 실제 도시 변화 확인

을 수행한 후 Final Movie와 인증서를 연다.

# 4. 기존 설계 진단

## 강점

- 교육과정 핵심 개념이 빠짐없이 들어가 있다.
- 기체라는 보이지 않는 대상을 **계측·연속 변화·가상 환경**으로 시각화하기 좋다.
- 전자저울, 온도 터널, 피스톤, 감압 챔버, 환경 시뮬레이터, 기체 관제, 장치 조립이 서로 다른 조작 방식을 가진다.
- Screen 01·07·09·10의 3D 사용 이유가 분명하다.
- 마지막 공기 장치 설계는 [4과15-04]와 직접 연결된다.
- 단순 정답 대신 재실험과 TEST가 가능하다.

## 게임성이 약했던 부분

- 각 화면이 “잘 만든 개별 활동”으로 보일 가능성이 있었다.
- Mission 사이의 Evidence 연결이 화면에서 충분히 강하지 않았다.
- 이전 Stage 완료가 도시 전체에 어떤 변화를 주는지 약했다.
- 마지막 화면이 자동 축하/인증서로 끝날 가능성이 있었다.

## 학습지형으로 보일 수 있는 부분

- Stage 1 증거 카드가 단순 카드 분류로 끝날 경우
- Stage 4 기체 정보가 카드 읽기 → 짝맞추기로 끝날 경우
- Stage 5 TEST가 사실상 정답 조립 한 가지로 고정될 경우

## 태블릿 활용이 약해질 수 있는 부분

- 온도 화면이 단순 슬라이더로만 구현되는 경우
- 압력 화면이 “누르면 커짐/작아짐” 애니메이션 한 번으로 끝나는 경우
- 기체 관제가 드래그 4번으로 끝나는 경우
- Final이 영상 감상만 하는 경우

## AI SLOP 위험

- 캐릭터 대사 → 활동 → 별 → 다음 버튼 패턴 반복
- 모든 Stage 하단에 똑같은 카드와 버튼
- 기체 카드의 색만 바꾸고 동일한 상호작용 반복
- 캐릭터가 화면마다 의미 없이 손가락으로 가리키는 연출

# 5. 단원 메인 퀘스트

## 사건 — 기체 도시의 공기 코어 정지

기체 도시는 공기의 흐름과 여러 기체를 이용해

- 계측 시설
- 온도 시험동
- 압력 제어구역
- 식품 포장·생활 시설
- 이동 장치

가 작동하는 연구 도시다.

어느 날 중앙 **공기 코어**가 멈추면서 도시의 다섯 구역이 차례로 정지한다.

문제는 단순한 전력 고장이 아니다.

각 구역의 센서와 기록이 서로 맞지 않아 **어떤 기체 조건이 문제인지 판단할 수 없는 상황**이다.

## NPC 의뢰

### 에어 — 여우 발명가

> “공기 코어를 그냥 켜면 또 멈출 거야. 먼저 도시 곳곳에서 무슨 일이 일어나는지 확인해야 해.”

학생은 도시를 다시 움직이기 위해 **5개의 연구 Evidence**를 모아야 한다.

## 최종 목표

5 Mission을 통해 다음을 완성한다.

1. 공기가 이동해 장치를 움직인다는 **공기 흐름 기록**
2. 기체에도 무게가 있음을 확인한 **무게 측정 증거**
3. 온도·압력에 따른 부피 변화 **환경 실험 기록**
4. 기체의 성질과 쓰임을 연결한 **도시 관제 보고서**
5. 공기의 성질을 이용한 **복구 장치 설계도**

그 후 학생이 이 다섯 Evidence를 가지고 관제 본부로 돌아가 공기 코어를 직접 복구한다.

# 7. Mission 1~5 심화 설계

## MISSION 01 — 끊어진 공기 동력선

| 항목 | 내용 |
|---|---|
| 학습목표 | 공기가 공간을 차지하고 이동하며 장치를 움직일 수 있음을 경험한다. |
| 퀘스트 상황 | 도시 외곽 공기 라인이 끊어져 중앙 장치에 공기가 도달하지 않는다. |
| 학생 핵심 행동 | 도시 조사 → 파이프 연결 → 공기 발사기 길게 누르기 → 흐름 관찰 → 전후 비교 |
| 주요 상호작용 | 3D 제한 회전, 핫스팟, drag-snap, long press |
| Micro Loop | 연결 → 공기 흐름 확인 → 장치 미작동/작동 → 연결 수정 → 재시도 |
| 실패/재시도 | 파이프 방향이 맞지 않으면 공기가 중간에서 멈추거나 새는 연출 |
| 과학적 피드백 | 공기 흐름이 투명 관을 따라 이동하고 끝의 팬/장치가 실제로 움직임 |
| Evidence | **공기 흐름 기록** |
| World Change | 외곽 파이프 조명 점등, 멈춘 소형 장치 재가동 |
| 유지 | 3D 도시, 파이프 연결, 길게 누르는 발사기 |
| 개선 | 단순 “연결 성공”이 아니라 전/후 장치 변화를 기록 |

## MISSION 02 — 보이지 않는 무게의 증거

| 항목 | 내용 |
|---|---|
| 학습목표 | 실험을 통해 기체에도 무게가 있음을 설명한다. |
| 퀘스트 상황 | 도시의 물류 계측기가 기체 용기를 잘못 판정해 운송 시스템이 멈췄다. |
| 학생 핵심 행동 | 수평 맞추기 → 영점 → 측정 → 공기 상태 변화 → 재측정 → 자료 검증 |
| 주요 상호작용 | bubble level, zero button, pump swipe, 기록 저장, evidence drag |
| Micro Loop | 측정 → 기록 이상 → 조건 확인 → 재측정 → 비교 |
| 실패/재시도 | 영점/수평 오류를 막지 않고 잘못된 기록으로 남겨 학생이 스스로 판별 |
| 과학적 피드백 | 공기 상태를 달리했을 때 비교 가능한 측정값이 달라짐 |

시설 요구 조건과 선택한 기체, 선택 근거.

**학습 증거:** 여러 기체의 성질을 조사하고 생활 속 쓰임과 연결함.

## 5. 공기 장치 설계도
학생의 실제 부품 구성, 공기 이동 경로, TEST 기록.

**학습 증거:** 기체의 성질을 이용한 장치를 설계·제작·수정함.

# 14. Final Mission

## 이름
**FINAL MISSION — 중앙 공기 코어를 다시 움직여라**

## 핵심
학습 내용을 마지막으로 실제 시스템에 적용한다.

## 행동

1. 자신의 3D 공기 장치를 코어 포트에 끼운다.
2. 노즐 방향이 코어 쪽인지 확인한다.
3. 투명 관의 끊김 여부 확인.
4. 두 밸브 중 공기 저장부 쪽을 먼저 연다.
5. 에어 발사기를 길게 눌러 흐름을 발생시킨다.
6. 코어 게이지가 목표 범위에 들어왔을 때 복구 레버를 직접 당긴다.

## 실패
- 노즐 반대 → 공기가 바깥으로 빠짐
- 밸브 순서 오류 → 공기가 저장되지 않음
- 연결 누락 → 중간에서 흐름 중단

## 피드백
“틀렸습니다” 없음.

현상 자체로 실패 원인을 보여준다.

## 성공
공기 흐름이 코어까지 도달 → 코어 회전 → 도시 파이프 전체 점등.
