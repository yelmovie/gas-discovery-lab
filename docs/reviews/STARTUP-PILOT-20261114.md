# 15번 기체 도시 대작전 · 첫 화면 로딩 개선

첫 화면과 인트로 세 장면을 유지했다. 지도에 진입할 때 지도 코드, 경로 데이터, 배경과 캐릭터 그림을 함께 요청한다. 각 시설의 실험 코드와 전용 스타일, 자동 관찰 도구는 그 실험에 들어갈 때 받는다. 공기 장치 미션과 개념 영상 조작 코드도 각각 열 때 받는다. 기존 오프라인 준비 기능은 전체 자료를 보관하는 별도 경로로 유지했다.

지도 코드가 막히면 **다시 열기**는 현재 지도 주소를 새로고침한다. 그림이나 경로 자료가 실패한 경우에는 지도만 다시 준비한다. 지도 없이 진행할 때는 **첫 실험 시작** 또는 현재 열려 있는 다음 의뢰로 들어갈 수 있다. 코드 대기는 10초, 지도 자료 대기는 20초로 제한했다.

| 지표 | 로컬 전 → 후 | 느린 환경 전 → 후 |
| --- | ---: | ---: |
| 접속 → 시작 버튼 조작 가능 | 49 → 32 ms | 1,032 → 592 ms |
| 첫 내용 표시(FCP, 초기 안내 포함) | 72 → 28 ms | 516 → 300 ms |
| 첫 화면 주요 콘텐츠 표시(LCP) | 72 → 60 ms | 1,380 → 1,048 ms |
| 인트로 종료 → 지도 준비 | 105 → 144 ms | 2,328 → 2,396 ms |
| 시설 안내에서 의뢰 선택 → 첫 실험 조작 가능 | 35 → 40 ms | 50 → 224 ms |

같은 Mac에서 변경 직전과 변경 후의 정적 배포 빌드를 비교했다. Chrome 1280×800, 동작 줄이기, HTTP 캐시를 끈 새 브라우저에서 조건과 버전별 5회 교차 실행의 중앙값이다. 느린 환경은 다운로드 10 Mbps, 지연 40 ms, CPU 4배 감속을 적용했다. 첫 화면의 JS·CSS 요청은 47 → 23개, 압축 전 JS는 228 → 109 kB, CSS는 162 → 117 kB였다. 첫 화면·인트로·지도에서는 실험 모듈이 요청되지 않았고, 첫 실험에서는 나머지 네 시설의 실험 코드를 받지 않았다.

- 지도 코드, 마을 그림, 경로 데이터를 각각 차단했다. 차단을 풀고 재시도하면 지도가 열렸고, 계속 막아 둔 경우에는 지도 없이 첫 실험을 열어 터치로 관을 돌리고 팬을 작동시켰다. 홈으로 돌아가 새로고침해도 증거가 남았고 **모험 이어가기**로 두 번째 실험이 열렸다.
- 지도 코드와 그림 응답을 보류했을 때 각각 약 10.3초와 20.4초 뒤에 실패 안내가 나왔고 첫 실험으로 들어갈 수 있었다. 지도 로딩 중 홈으로 나가도 늦게 끝난 요청이 홈을 덮지 않았다. 첫 실험 코드만 차단한 경우에도 차단 해제 후 **다시 열기**가 작동했다.
- 공기 장치 미션을 따로 열고 닫은 뒤 버튼으로 키보드 초점이 돌아왔다. 정적 배포 빌드와 단위 테스트 66개가 통과했다. 기존 브라우저 검사에서 전체 20개 의뢰·마지막 복구·인증서·다시 탐구·키보드 조작, 개념 영상 10종의 구간 이동과 실패 대응을 확인했다.
- 운영 주소는 유지했고 배포하지 않았다.
