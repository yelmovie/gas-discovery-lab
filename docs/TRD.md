# 기체 도시 대작전 TRD 초안

상태: 구현 전 기술 제안 · 2026-10-14

저장소에 실행 코드·패키지·압축파일은 없었어. 제공 문서의 Phaser·Three.js·DOM 구성 중 이번 요청에 필요한 부분만 제안하며, 아직 의존성을 설치하지 않았어.

## 화면 구성 제안

- TypeScript와 Phaser로 2.5D 지도 및 2D 조작을 구성하고, 글자·버튼·기록·설정은 공통 DOM UI로 분리해.
- 선택 지도는 확정된 숲·강·언덕 속 연구시설 5곳을 고정 사선 시점의 타일/이미지와 캐릭터 스프라이트로 표현해. 발 위치의 y값을 기준으로 앞뒤 가림을 처리해.
- 실내에는 사선 RPG 카메라나 자유 회전을 적용하지 않아. 기존 배경 위에 독립 조작 오브젝트를 얹어.
- Three.js는 초기 필수 의존성으로 두지 않아. S09의 선택형 3D 확대 보기를 확정할 때만 추가해.
- 메인·지도·활동·최종 화면 모두 하나의 공통 UI 셸을 사용해.

```text
AppShell
  GlobalControls: Home / Back / Sound / Settings
  Main
  WorldMap
  Activity: S01 ... S09
  Finale: Report → Repair → Ending → Complete
  ResearchBag
```

## 상태와 저장 제안

```ts
type SaveData = {
  version: 1;
  currentScreen: string;
  mapPosition: { x: number; y: number };
  completedMissions: string[];
  evidence: EvidenceRecord[];
  measurements: MeasurementRecord[];
  volumeComparisons: VolumeComparison[];
  deliveryResults: DeliveryResult[];
  deviceDesign: DeviceDesign | null;
  testHistory: DeviceTest[];
  finaleCompleted: boolean;
  settings: { muted: boolean; adminUnlockAll: boolean };
};
```

위 타입은 개념 초안이고 참조 타입은 구현 시 정의해. 저장 공간에는 PNG 스냅샷 대신 기록 시점의 실험 상태·부품 배치 데이터를 저장하고, 썸네일은 다시 렌더해. 상태 변경 후 저장하며 손상된 데이터는 그대로 덮어쓰지 않고 새로 시작·복구 선택을 제공하는 안이야.

접근 허용은 `adminUnlockAll || 정상진행조건`으로 계산하되, 학습 완료는 실제 증거와 성공 이벤트로만 판단해. 관리자 미리보기 데이터는 실제 저장 기록과 분리해. 로컬 관리자 해금은 수업·검수용 편의 기능이며 서버 권한 기능을 뜻하지 않아.

## 활동 모델의 원칙

- 관 연결: 포트와 방향을 가진 그래프로 검사하고, 공급원에서 목표까지 경로가 이어지는지 계산해.
- 공기 흐름: 공급 동작과 연결 상태로 팬 반응을 표현해. 빛은 경로 표시로 사용하며 기체 입자를 뜻하지 않아.
- 무게: 같은 용기 ID, 수평, 영점, 공기량 조건을 기록해 비교 가능성을 판정해. 정확한 가상 수치와 오차 모델은 교육 검토 후 확정해.
- 온도: 기체량을 유지하고 움직일 수 있는 막의 부피를 변화시켜. 압력 비교와 동시에 여러 조건을 바꾸지 않아.
- 압력: 닫힌 피스톤 또는 유연 용기를 사용하고 기체량·온도를 유지하는 비교를 설계해.
- 기체 공급: 시설 요구, 선택 기체, 근거를 기록해. 실제 의료·가스 기기 사용법이 아닌 가상의 시설 문제 해결로 표현해.
- 장치 시험: 연결·밀폐·방향·공급 상태를 검사해 결과를 내고, 특정 부품 위치 하나만 정답으로 고정하지 않아.
- 최종: 보고 완료 → 장치 연결 → 유효한 공급 → 복구 조작을 상태 전이로 구분해. 임의 밸브 순서 암기는 구현하지 않아.

## 입력과 에셋

- 지도 이동은 탭한 길로 이동하는 방식과 키보드 이동을 제안해. 장애물·입구 영역·서 있는 위치를 분리해.
- DOM 모달이 열리면 게임 입력을 멈추고 닫으면 복구해. 같은 터치가 버튼과 게임에 중복 전달되지 않게 해.
- 픽셀 지도만 정수 배율과 최근접 샘플링을 적용해. 실내 이미지와 DOM 글자에는 같은 픽셀 확대를 강제하지 않아.
- 배경의 글자·수치·분자 그림·고정된 움직임 표시를 학습 UI로 재사용하지 않아.
- 기존 포즈 모음은 자동 보행 시트가 아니야. 플레이어의 방향별 걷기 프레임과 발 위치 기준을 별도로 제작해야 해.
- 원본은 `assets/references`에 보존하고 실제 사용본은 구현 시 별도 경로에 만든다. 현재는 원본 변환을 하지 않았어.

## 구현 후 필요한 검증

- 미션 완료와 전체 해금이 분리되는지, 저장 복원이 되는지 확인.
- 잘못된 조건의 측정 기록을 증거로 채택하지 않는지 확인.
- 두 개 이상의 유효 장치 연결과 끊김·역방향 실패를 확인.
- 지도 이동 → 입장 → 기록 → 지도 변화 → 최종 복구의 흐름을 실제 브라우저에서 확인.
- 태블릿 두 규격에서 터치·드래그 대안·모달·아이콘 위치를 확인.

현재는 문서와 에셋만 검토했으므로 빌드·게임 기능 테스트 결과는 없어.
